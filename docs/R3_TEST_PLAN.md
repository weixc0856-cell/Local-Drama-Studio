# R3 测试计划：竖屏能力与单篇完整成片

> 前置：R0/R1/R2-A/R2-B 已提交（`4d72a0b`、`226fdf3`、`026509b`）。
> R2-B 已给出能力边界：Wan 适合缓慢推近，不可靠地控制精确主体位移。
> 本阶段不再优化 H3/Wan 主体控制，不引入新模型、不安装 SeedVR2。

## 1. R3 的三个子阶段

| 阶段 | 目标 | 产物 |
|---|---|---|
| R3-A | 原生竖屏能力测试 | 576×1024 的 FLUX 图与 Wan 视频，记录耗时/显存/质量 |
| R3-B | 单篇完整成片 | 30-60 秒、9:16、1080×1920、1-2 段 Wan、4-6 张静帧、配音、字幕、FFmpeg |
| R3-C | 真实生产成本验收 | 端到端耗时、人工时间、失败率、夜间批次可行性 |

## 2. 生产配方（待验证）

```text
每篇作品：4-6 张 FLUX 静态画面 + 1 段 Wan 英雄镜头
成片：30-60 秒 / 9:16 / 1080×1920
Wan 不足时：静态画面 + FFmpeg 缓慢推拉/横移补足
```

这不是已验证的最佳配置，而是 R3 要验证的初始配方。

## 3. R3-A：竖屏能力

### 3.1 规格

| 环节 | 规格 |
|---|---|
| FLUX 静态图 | 576×1024，4 步，CFG 1.0 |
| Wan 动态视频 | 576×1024，73 帧，20 步，`uni_pc`/simple，shift 8，CFG 5 |
| FPS | 24 |
| 最终成片 | 1080×1920（R3-B 用 FFmpeg Lanczos 放大） |

576×1024 与 1024×576 像素总量相同，且宽高都能被 32 整除。**像素量相同不等于耗时/显存相同，必须实测。**

### 3.2 任务

| Job | 内容 | 参数 |
|---|---|---|
| V1 | 竖屏江月静帧 | FLUX 576×1024，seed 4101 |
| V2 | 竖屏花林静帧 | FLUX 576×1024，seed 4201 |
| V3 | 花林推近动态（源 V2） | Wan 576×1024，73 帧，seed 4301 |
| V4 | 江月缓慢推近（源 V1） | Wan 576×1024，73 帧，seed 4401（时间允许才跑） |

### 3.3 记录

- 耗时、峰值显存、输出尺寸、解码结果。
- 画面：主体/背景是否稳定，是否出现纵向拉伸、黑边、构图崩坏。
- 与 1024×576 的 R2 数据对比，但不假设线性。

### 3.4 验收

- `PASS_VERIFIED`：576×1024 的 FLUX 与 Wan 均成功，无 OOM，画面无拉伸/黑边，成本有记录。
- `PASS_LIMITED`：需要降级或仅一方成功。
- `FAIL`：竖屏 Wan 无法生成。
- `NOT_RUN`：未执行。

## 4. R3-B：单篇完整成片

30-60 秒、9:16、1080×1920。建议结构：

| 段落 | 画面方式 |
|---|---|
| 开场 | Wan 动态江月/花林（≤1 段） |
| 春江 | FLUX 静帧 + 缓慢运镜 |
| 海上明月 | FLUX 静帧 + 轻微粒子/雾 |
| 花林 | Wan 推近（复用 H2/V3 的运动方式） |
| 孤舟 | 静帧 + 后期合成，不要求 Wan 控制船只 |
| 结尾 | 晨曦静帧 + 渐隐 |

- Wan 镜头最多 2 段。
- 静帧 4-6 张。
- 配音：CosyVoice（复用 `D:\AI\CosyVoice-Runtime`）。
- 字幕：自动生成并人工检查。
- 剪辑：FFmpeg 自动合成；1080×1920 用 Lanczos 放大。
- 失败降级：Wan 失败可退回静帧 + 推拉。
- 验收：不需要重新剪辑就能正常观看。

## 5. R3-C：真实成本

记录：

- 从输入篇目到最终 MP4 的总墙钟时间。
- 各环节耗时：FLUX、Wan、TTS、字幕、FFmpeg、人工检查/返工。
- 失败率与降级次数。
- 是否适合“每晚跑一个批次，第二天得到若干条可审核竖屏视频”。

## 6. 边界

- 不做 121 帧测试。
- 不做原生 1080p 生成；只用 FFmpeg 放大。
- 不安装 SeedVR2 或其他新模型/依赖。
- 不开发自动发布。
- 不继续优化 H3/Wan 的精确主体位移。
- 所有新增依赖必须说明必要性；当前计划不新增 Python 依赖。
