# Literary Intelligence — L0 风险清单

> 日期：2026-11-03
> 本文件记录会导致“看起来能用、实际不能发布”的风险。风险未关闭前，不得进入 L1 之外的生产链路。

## 1. 许可风险

### R1 HanLP 模型非商业

- 官方 README：代码 Apache-2.0，但**除非另有说明，所有模型为 CC BY-NC-SA 4.0**。
- 古汉语模型页没有单独的宽松许可。
- 影响：模型推理、生成内容、随项目分发都可能受非商业/相同方式共享条款约束；训练数据（EvaHan/UD）许可也需单独核验。
- 缓解：不得作为商业生产依赖；如研究，需取得明确许可或只使用不构成发布的内部实验。
- 状态：`PARTIAL`（技术可用性有证据，商业许可未通过）。

### R2 Jiayan 模型来源不明

- 代码 MIT，但模型通过百度网盘/Google Drive 分发，README 未给模型许可、哈希、大小。
- 影响：无法证明模型可商用、可再分发、可重复构建。
- 缓解：不接入；如研究，先建立模型资产登记并核对许可。
- 状态：`NOT_RUN`（模型）。

### R3 CTP 抓取/订阅限制

- 官方页面明确禁止 scraping、会返回 corrupted data；API 通过订阅提供。
- 影响：不能把 ctext.org 当作可批量抓取/缓存的免费语料。
- 缓解：如使用，取得订阅/API 授权，记录缓存/引用范围，不进行网页抓取。
- 状态：`PARTIAL`（访问机制有证据，商业/再分发未确认）。

### R4 CNKGraph 非商业

- 官方页面明确“仅限非商业用途”。
- 影响：不得用于商业内容生产的正式数据源。
- 缓解：仅作研究参考；商业链路排除。
- 状态：`NOT_RUN`（商业）。

### R5 Gujilab CC0 声明的上游风险

- 数据集/结构化处理声明 CC0；但来源包含 ctext.org、殆知阁、Wikisource、NiuTrans 等。
- 影响：数据集的 CC0 声明不一定覆盖上游文本的访问、注释、翻译和再分发条款。
- 缓解：下载前做来源级审计；优先只使用可独立核验的公有领域原文；不把今译/注释默认视为 CC0。
- 状态：`PARTIAL`（高风险）。

## 2. 运行时与依赖风险

### R6 HanLP 需要 torch

- `hanlp==2.1.1` 依赖 `torch>=1.6.0`、`transformers>=4.1.1`。
- 项目根 `.venv` 明确不安装 torch；ComfyUI 的 XPU 环境也不能作为文学生产环境。
- 影响：直接安装会违反环境约束并引入大型依赖。
- 缓解：如批准研究，另建隔离 Runtime，记录版本、磁盘、运行方式；不进入根环境。

### R7 模型体积/下载

- HanLP 古汉语模型约 `450,378,307` bytes。
- Gujilab 数据集约 823 MB。
- 影响：下载、磁盘、模型加载时间和可重复性成本。
- 缓解：本阶段不下载；需要时先报告来源、大小、许可和运行要求，取得批准。

### R8 Jiayan 依赖 KenLM

- README 要求额外安装 KenLM 源码；模型为外部文件。
- 影响：安装不可复现、许可/构建链复杂。
- 缓解：不接入；如研究，锁定 commit 和构建方式。

## 3. 数据与解释风险

### R9 原文版本不固定

- 《洛神赋》存在不同版本、标点、异文和注释传统。
- 影响：同一句话的“原文”可能不同；无法定位就无法核验。
- 缓解：L1 必须先固定底本、整理者、出处、locator、SHA-256；未确认则标 `UNVERIFIED`。

### R10 解释冒充事实

- 文学赏析中“鸿雁象征什么”“游龙体现什么”常是解释，不是原典事实。
- 影响：LLM 很容易把解释写成客观结论。
- 缓解：每条 claim 强制标注 `original_text / historical_fact / interpretation / creative`；没有来源的事实不得进入讲解稿。

### R11 LLM 幻觉

- 本地 LLM 可能编造典故、作者生平、出处和 source_refs。
- 影响：内容看似有文化，实际不可核验。
- 缓解：只提供已登记证据；要求 claim_id/source_refs；设计无来源反例；人工审核前保持 `unreviewed`。
- 当前状态：服务与客户端已就绪（2026-11-03：8080 在线，`Qwen3-30B-A3B-Instruct-2507`，CPU-only，64K；`run_li15.py` 可调用）；真实五轮输出未落盘，幻觉风险尚未实测。

### R12 FTS5 中文检索误判

- 本机 `unicode61` 和 `trigram` 对 2 字中文查询均不命中；`trigram` 需要 3 字以上。
- 影响：短词“惊鸿”“游龙”直接查询会漏检。
- 缓解：L1 使用 trigram + 2 字 `LIKE` 回退/辅助 bigram 表；测试必须覆盖 2 字、3 字、长句和标点。
- 状态：`PASS_VERIFIED`（FTS5 可用）；`PARTIAL`（中文查询设计）。

## 4. 工程风险

### R13 现有未提交工作

- 工作区有 S3-A/S3-B 未提交修改和字体资产。
- 影响：任何 reset/checkout/clean 都可能丢失工作。
- 缓解：本阶段只新增 `docs/literary_intelligence/`，不修改生产代码，不暂存、不提交。

### R14 误把研究工具当生产依赖

- HanLP/Jiayan 的代码许可、模型许可、数据许可彼此不同。
- 影响：把 Apache-2.0/MIT 代码许可扩大解释为模型/数据可商用。
- 缓解：资产级登记；代码、模型、数据、生成内容分别核验。

## 5. 停止条件

出现以下情况必须停止并报告，不得自行绕过：

- 需要下载模型权重/大型数据集但未获批准；
- 需要安装 torch 或全局依赖；
- 需要修改根 `.venv`；
- 需要抓取 CTP 或使用 CNKGraph 商业数据；
- 无法固定原文版本/来源；
- LLM 无法区分无来源事实；
- 任何操作会覆盖现有 S3-A/S3-B 工作。
